04  TICKET COMMENTS ARE PRIVATE BY DEFAULT

WHAT
  A ticket comment has a conversation type: 1 Public, 2 Private, 3 Side Conversation,
  4 Approval. When the caller does not say, this server uses 2, Private. Who gets emailed:
    Public (1)             the ticket contact and the CCs.
    Private (2)            nobody.
    Side conversation (3)  the recipients of that side conversation.
    Approval (4)           the approvers of that approval.
  Creating a side conversation or an approval sends nothing by itself. Email goes out when a
  comment is posted into it. Related: creating a ticket with SendTicketCreatedEmail true emails
  the contact, so that option is explicit and described in the tool text.
  The server instructions tell the model to say who will be emailed before posting anything
  that is not Private. Approvers must be contacts carrying an approver tag. The approver mark of a
  tag is set in the Gorelo app. update_contact with the complete tag list (the contact's
  current TagIds plus that tag) gives a contact that tag; it has not been tried live whether
  this makes the contact eligible as an approver.

WHY
  A comment sent to a customer cannot be recalled. A private note that should have been public
  costs one extra step; a public note that should have been private can leak internal opinion,
  a password hint or a wrong diagnosis to a client. The failure modes are not symmetric, so the
  default is the safe side. The same reasoning applies to who gets mailed: the model must state
  it, so the human can stop the call.

WHAT IT COSTS
  A model that forgets to set the type will write an internal note when a reply to the customer
  was intended. The technician sees this quickly (nothing arrives) and can ask again with Public.
  It is a deliberate bias toward "no email".

WHERE IN THE CODE
  tools/conversations.py     Module docstring and the comment tools. The conversation type
                             mapping (ConversationTypeId) and the default of Private.
  server.py                  INSTRUCTIONS, rule 5 (who a comment emails).
  tools/projects.py          The same rule for project comments (create_project_comment, where
                             the default conversation type 2, Private, is set).
  tools/project_tasks.py     The same rule for task comments (task comments other than Private
                             put the task in a waiting-on-contact state).
  docs/API-OBSERVED-BEHAVIOR.md        Where production differed from the published spec.
