10  TOOLSETS, AND WHY PROJECTS, FORMS AND DOCUMENTS ARE OFF BY DEFAULT

WHAT
  Tools are grouped into toolsets: core, tickets, time, billing, uptime, projects, forms and
  documents. GORELO_TOOLSETS chooses which are registered (a comma list, or all, which includes
  documents). The default is core, tickets, time, billing, uptime. projects, forms and documents
  are off. An unknown name stops the start with an error that lists the valid ones. With the
  defaults the server registers 63 tools; with all toolsets 101 (more with the gated tools,
  see 03).

WHY
  Three reasons.
    1. Gorelo API keys carry per-area scopes. A key without the Project, Forms or Documents
       scope gets an HTTP 403 (notification code 080203) on those tools. Registering tools that cannot work
       gives a model more to choose from and more ways to fail.
    2. Context size. Every registered tool is described to the model in every conversation. A
       smaller list is cheaper and less confusing (see 09).
    3. Least privilege. Project and form tools can change work the typical help desk does not
       touch, and document tools read and write the written knowledge of the business and of its
       clients (and, through share_document, can make a document public). You opt in when you
       have decided to let an assistant do it, and you scope the key to match.
  Projects had a further reason: those tools were first tested offline only and follow the published spec text.
  They are less proven against live behavior than the others.

WHAT IT COSTS
  A user who wants a project or document tool has to ask the operator to enable it and widen
  the API key. Files and images for a document are uploaded with upload_attachment, which is in
  tickets, so documents without tickets cannot attach a file.
  The model will say a tool does not exist rather than offer it, until the toolset is on.
