05  A BUILT-IN OAUTH PROVIDER WITH ONE PASSWORD

WHAT
  claude.ai connects to a remote MCP server through OAuth 2.1. This server is its own OAuth
  provider. When an AI client first connects it registers itself, is sent to a consent page, and
  you type one password (MCP_AUTH_PASSWORD). If it matches, the client gets an access token
  (prefix pat_) and a refresh token (prt_). After that the client refreshes by itself.
  Around that sit these rules:
    - The page checks the whole request first (registered client, allowed redirect address,
      PKCE) and only then compares the password, last, in constant time. Every invalid request
      gets the same page.
    - Redirects are allowed only to claude.ai, claude.com or localhost. An authorization code
      never goes anywhere else.
    - Wrong passwords are counted per client address: 5 per address in 15 minutes and 30 an
      hour from all addresses together, then HTTP 429 (even for the right password).
    - Client registration is open by design (the protocol needs it) but limited: 10 an hour per
      address, 50 a day overall, at most 50 clients kept, 16 KiB body cap.
    - Refresh tokens rotate: using one retires it, and only its sha256 is kept so a replay is
      noticed and logged. /revoke is on.
    - Tokens live in one state file (.oauth-state/oauth_tokens.json), written atomically (write
      a temp file, fsync, rename) while holding an exclusive lock, mode 0600 in a 0700
      directory. A file that cannot be trusted stops the start instead of being replaced.
    - The server refuses to start without a password, or on a fastmcp or mcp version the gate
      was not checked against.
    - An EXPIRED access token is refused and nothing else changes. Its refresh token is kept.

WHY
  Why not a hosted identity provider: this is a single-operator tool, and an extra account
  and service to trust and maintain would be more moving parts than one password page. Why the
  password must be long: it is the only thing between the internet and a Gorelo key. The server
  logs a warning when it is shorter than 16 characters.
  The last rule comes from a failure seen in an earlier version. The framework's default, when shown an expired access
  token, also deleted the matching refresh token. So when a 30-day access token expired,
  claude.ai had nothing to refresh with and the connector failed until the user signed in again
  on the password page. Refusing the expired token
  without touching anything else lets the client refresh quietly.

WHAT IT COSTS
  One shared password means all-or-nothing access: anyone who knows it gets every tool. There
  are no per-user permissions. The state file is a secret and needs backups (a restore from an
  old backup forgets sessions made since, and each refresh since). The limiter counts per
  address, so it depends on seeing the real visitor address through the tunnel; the deploy
  checks the log shows public addresses and not 127.0.0.1. Access tokens last 30 days
  and refresh tokens do not expire, which is a trade for fewer sign-ins.
